輪迴檔案館 Chrome 擴充功能 V0.6.6

新增兩項功能（仍需要先為這個 ChatGPT 對話綁定正確輪迴、開啟監看）：
1.「↓ 從現在畫面掃描到底」：從當前頁面直接向下捲動到對話最底端，掃描時不固定起點 DOM；即使起始訊息滑出畫面，也會從後續新載入訊息接著掃描。
2.「▧ 在頁面框選範圍」：按下後回到 ChatGPT 頁面，點第一則訊息作為起點，能用滾輪、捲軸或拖動頁面選擇終點，亦可在訊息上按住滑鼠拖曳跨回合。浮動面板顯示範圍，按確認上傳才會傳送；取消不會傳送。

兩種模式都要求「每則皮卡發言後必須有副駕駛 GPT 回應」。若遇到一則皮卡訊息尚無 GPT 回應，會停止在前一組，後續不跳號。長訊息若無法展開、超過 25,000 字或缺少穩定的 DOM 回合識別碼，會中止／拒絕，避免傳送錯誤正史。

為了不讓選單視窗關閉使操作消失，掃描及框選期間，ChatGPT 頁面右上角會有浮動面板、目前進度與取消按鈕。發送時逐則依序，遇到網路錯誤就停下；已成功傳送的資料不會撤回，重新操作可依相同來源 ID 去重。

時間：沿用現有的原始時間／首次擷取／兩個角色同分鐘推定規則。如開啟「自動讀取時間」，掃描到可見的回覆時會嘗試讀取選單時間；無法確定時仍維持未知，使用首次擷取排序。

保留 V0.5.6 的「顯示較少」末尾清理，亦保留原本『目前已顯示歷史回補（最多200）』及一般監看模式。

安裝：解壓縮 ZIP，使用六個檔案覆蓋原擴充功能資料夾，前往 chrome://extensions 按「重新載入」；ChatGPT 頁面 F5。確認版本 0.6.6。
不需要重新部署 Firebase Functions，也不必重新設定綁定／金鑰。

V0.5.9：新增「本次掃描重新傳送已傳過的訊息」勾選框。僅手動向下掃描／框選範圍時才生效，普通監看仍照既有去重。重傳時 Firebase 對尚未刪除的來源仍會去重；請先在輪迴檔案館 V5.5 的指定輪迴清空舊版副駕駛聊天（含原始收件），再使用重傳模式。

V0.6.0 — 慢速防漏／雙向配對修正：
1. 原先向下掃描若所有前一批 DOM 訊息離開畫面，會把下一批直接當成連續；現在不允許，必須有重疊回合。
2. 捲動由每步 60% 視窗縮成最多 18%、220 像素，並延長等待時間；接續失敗自動回捲最多四次，仍未連上立即停止。
3. 皮卡與 GPT 每則都必須有相鄰對應訊息，雙向核驗。首則是找不到玩家的 GPT 不再默默跳過。
4. 任一處缺角色、缺穩定 ID、接續不明、顯示較多未展開，都不會上傳整批。只有完整檢查結束後才逐則上傳。
5. 既有 V0.5.9 重傳功能及 Firebase 後端 API 保持不變，不用重新部署。
6. 重要：本版不能自動修復已經上傳且錯序或缺漏的舊內容。請在檔案館核對與備份，必要時清空指定輪迴副駕駛聊天與來源，再重掃。

V0.6.1 — 單項速度調整試驗：
將每一步向下捲動幅度由視窗高度的 18%（最多 220 px）改為 30%（最多 360 px）。
等待 850 ms、穩定等待 340 ms、雙向配對與 DOM 接續完整性檢查保持不變。
此版本只調整捲動幅度，供同一電腦逐步測試速度與缺漏情況。

V0.6.2 — 折疊訊息可靠展開：
1. 保留 V0.6.1 30% (最多360 px)、850ms等待、雙向配對與漏掃保護。
2. 歷史範圍掃描不再依賴一般監看使用的全域「已嘗試點開」紀錄。
3. 遇到「顯示較多」，會針對仍在頁面的該則訊息自動點開，重新讀取 DOM 內容並驗證，最多重試 4 輪；不限制按鈕必須在可視範圍中。
4. 若無法展開，當場停止且顯示第幾則、皮卡/GPT 及片段內容，整批 0 則上傳，不會掃完很久才報錯。
5. 選單時間查詢後再次驗證長訊息，以避免選單引起的重新渲染將訊息重新折疊。
6. 不刪除正文的「...」或強行把未展開內容當完整內容。仍不能確定的訊息會報錯而不是入庫。

V0.6.3 — 單項速度折衷測試：
1. 每一步向下捲動幅度由 30%（最多 360 px）改為 24%（最多 288 px）。
2. 捲動等待由 850ms 改為 600ms；穩定等待 340ms 保留。
3. 雙向配對、DOM 接續驗證、展開重試與遇錯整批 0 上傳等保護保留。
4. 注意：變更捲動速度不代表能解決「顯示較多」展開失敗，若仍報錯請保留截圖與訊息位置供後續處理。

V0.6.4 — 下一輪速度測試：
1. 單步捲動由 24%（最多 288 px）改為 27%（最多 324 px）。
2. 捲動等待由 600ms 改為 477ms；穩定等待 340ms 保持不變。
3. 雙向配對、重疊檢查、折疊訊息重試、0 上傳安全機制均保留。
4. 網站另外更新「我／他」分隔符：除了 ： : 也接受 ” 和 ；。分類是網站收取時執行的，擴充功能不應更改你的原始字串。

V0.6.5 — 嚴格起點及玩家氣泡辨識：
1. 必須從皮卡→GPT 完整回合起頭。無法核對前置皮卡則停止，不跳過 GPT、不中途補猜。
2. 若新版 ChatGPT 只保留 bg-user-message 而無 group/user-message，仍可辨識；背景色 rgb(232,243,254)/#E8F3FE 只作輔助，絕不單靠色號認定玩家。
3. 新版/舊版混合回合排序以同回合皮卡在前、GPT 在後；最終上傳前再次驗證。
4. 捲動仍為27%/324px、等待477ms；需重載擴充功能並刷新 ChatGPT。

V0.6.6 — 對應輪迴檔案館網站 V5.31 的劇情時間診斷：
1. 在助手彈窗新增「Gal AI 劇情時間與跳過線索（唯讀）」；只偵測目前 ChatGPT 網頁已載入的皮卡貼文，並列出「他：」段落頂端時間範例。
2. 同時偵測 made in heaven／做愛跳過，僅提示疑似自行跳過劇情；不把它計算成缺漏數。
3. 完整歷史掃描上傳前及完成後，顯示本批已驗證訊息中的劇情時間與跳過線索數量（不同來源可能重複，不可直接用來推算缺漏）。
4. 不修改送給 Firebase 的原文字、來源 ID、ChatGPT 發言時間、雲端格式和去重規則；Gal AI 劇情時間由網站 V5.31 判斷及套用到同回合「我／他」。
5. 完整保留 V0.6.5 的27%／477ms慢速掃描、折疊展開、嚴格雙向回合驗證與本批不完整不傳送。
6. 更新方式：先停止監看，備份原擴充資料夾，再將此 ZIP 內六個檔案覆蓋原檔案夾，在 chrome://extensions 按「重新載入」，並刷新 ChatGPT 頁面。不要刪掉原擴充功能或重新建立金鑰。

V0.7.0 — 新增完全獨立的 Gal AI 網頁掃描器（不是 ChatGPT 掃描改名）：
1. 點擴充功能後，選「🌐 開啟 Gal AI 原生正史掃描器」，在 Gal AI 原始對話分頁為該頁面另行綁定世界觀、輪迴 ID（可從原設定帶入副駕駛名稱）。
2. 從第一則左側無時間的輪迴開場開始，按「從現在畫面掃描到底」。固定每步視窗高度20%，最多350px，等待400ms後再穩定350ms。原 ChatGPT 27%／477ms 工具完全保留。
3. 新模式不開啟 ChatGPT 訊息選單，不用「顯示更多／展開時間」。第一則歸「輪迴開場」，其後逐組「我／他」，另掃描符合事件標記的 Gal AI 原文。玩家與 AI 共用 Gal AI 回覆狀態表時間；不使用現實發言、首次擷取或雲端接收時間。
4. 優先保留 DOM 的藍色引用框（轉為 Markdown >）及特殊斜體（*文字*），保留正文；若網站 DOM 格式無法辨認、沒有完整開場、回合不成對、訊息超長、捲動視窗無重疊，停止且不匯出不完整正史。
5. 掃描後按網頁右上角的「下載原生正史 JSON」，檔案館 V5.35 使用「🌐 Gal AI 原生正史覆蓋」核對與匯入。這份原生資料可優先覆蓋指定輪迴的開場、完整對話、事件簿，但必須先預覽及備份；副駕駛聊天、筆記等其他欄位不受影響。
6. 事件接取狀態不會從文字瞎猜，匹配現有事件時保留使用者的已接狀態，新事件預設待接取；不匹配的舊已接事件須明確勾選額外覆蓋確認。
7. 本版是第一版通用 DOM 偵測；不同網站 UI 可能有專屬訊息容器。若畫面顯示「找不到可靠訊息容器」，請不要用半份 JSON 覆蓋正史，保留畫面與錯誤供下一版調校。
8. 避免不必要的網站權限：新模式按鈕使用 Chrome activeTab＋scripting 在使用者當下選定的頁面注入，不會長期掃描其他網站。掃描不直接傳送 Firebase；匯入僅改本機，核對後再手動同步雲端。

V0.7.1 — Gal AI 網頁泡泡辨識修正：
1. 修正 V0.7.0 尚未捲動就報錯「找不到可靠的訊息容器」：新增對匿名/動態 CSS 樣式的一般訊息容器偵測、滑動區辨識及避免把多段 Gal AI 回覆拆散的分組判定。
2. 若自動辨識仍不成功，網頁右上面板按「🎯 點選開場校準」，再點 Gal AI 第一則左側無時間的開場正文，按「🔁 重新掃描」。
3. 仍失敗可按「📋 複製版面診斷」取得捲動容器、候選訊息數、DOM 類別摘要供調整，診斷不包含對話正文。
4. 捲動仍固定20%／350px上限、400ms等待＋350ms穩定檢查。不擅自跳過開場、不在缺回合時匯出、也不直接上傳 Firebase。
5. 重要：需把新版 ZIP 全部覆蓋原擴充資料夾，在 chrome://extensions 按重新載入，並重新整理 Gal AI 頁面，才能取代既有 V0.7.0 注入腳本。
