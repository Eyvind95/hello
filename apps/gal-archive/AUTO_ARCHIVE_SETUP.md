# 輪迴檔案館 V5.31｜多輪迴、時間稽核與 Chrome 歸檔助手 V0.6.6

## 核心原則

- **世界觀可新增、重新命名，且沒有固定三個世界觀或第16周目的限制。** 一個世界觀下可以建立任意數目的輪迴。
- **每個 ChatGPT 對話只能在 Chrome 擴充功能中明確綁定一個目標輪迴**；每個對話可使用不同的輪迴文件 ID、負責副駕駛與世界觀標籤。切換聊天不會繼承上一個輪迴的 ID。
- Firebase `archiveIngest` 依傳入的 `cycleId` 導向已上傳的輪迴，並驗證當輪所允許的管理人。它沒有「只接受第16周目」的規則。
- 完整對話僅保存有明確「我：／他：」的 Gal AI 劇情；其餘玩家與副駕駛 GPT 討論進入「副駕駛聊天」。
- 時間排序（V5.31）：優先 Gal AI 回覆開頭的劇情時間，可信的「我／他」同回合共用；其次 ChatGPT 原始發言時間＝手動標註時間，再依序首次擷取與雲端接收。**劇情時間與現實時間是不同軸，絕不直接相減。**
- `incoming` 內的 `status: accepted` 表示已經收取，不代表收到了你想要的輪迴；網站現在會顯示已收取來源的輪迴位置。

## 日常使用步驟

1. 開啟 `https://eyvind95.github.io/hello/apps/gal-archive/index.html`，按「強制更新」，確認 V5.31。
2. 在左側新增／選擇世界觀，新增或編輯輪迴，填寫負責副駕駛（可多位，頓號隔開）。
3. 登入「☁ 雲端同步」，**先備份**，再按「↑ 上傳本機資料」。新輪迴必須先上傳，Firebase 才能接收；否則會得到 `cycle_not_found_upload_cycle_first`。
4. 選擇輪迴按「複製輪迴 ID」。注意它是 UUID，不是「第16周目」文字。
5. 在需要歸檔的 ChatGPT 對話開啟 Chrome 擴充功能 V0.6.6，填 UID、正確輪迴 ID、負責副駕駛和**原有寫入金鑰**；世界觀／輪迴名稱供辨識，不送雲端。
6. 點「將此對話綁定到上面輪迴」，確認綁定名稱，再按「開始監看此對話」。每次換 ChatGPT 聊天，須重新選取目的輪迴、明確綁定；可從已儲存輪迴清單選擇。
7. 收到新訊息後，在網站按「📥 分類收取自動紀錄」，**看清楚確認視窗列出的目的輪迴**再接受。
8. 需要修排序時，先匯出 JSON 備份，再使用「↕ 依時間校正自動歸檔順序」。

## 清理舊測試資料與誤收輪迴

- **清測試**：先選左側要處理的輪迴 → 「☁ 雲端同步」→「🧹 選取並清除測試訊息」。手動確認每一則、備份後才可移除。功能不會批次清空全部輪迴，也不會刪除手動寫入的正史。
- **搬錯輪迴**：先選收錯資料的「來源輪迴」→「↗ 轉移誤收的來源對話」→選原始 ChatGPT 對話與正確輪迴 → 備份後確認。只移具來源 chatKey 的自動歸檔，保留當時文字、時間與來源 ID。目標輪迴必須先允許對應的副駕駛。
- **原始收件匣**：以上清理／搬移不會刪除 Firestore `galArchive/{uid}/incoming` 的稽核來源（包含 `accepted`）。這是為了避免事後無法追回遺失的正史。
- **版本遷移**：舊版同一個監看對話的連線設定在安全條件下才會遷移；如果以前同時監看多個聊天，請逐一確認、重新綁定，不會默默使用第16周目的全域設定。

## 更新 Chrome 擴充功能，避免金鑰遺失

Chrome MV3 解壓縮擴充功能通常必須維持原本資料夾才能保留同一個擴充功能 ID 與其 local storage。

1. 停止監看所有對話；先不要移除舊擴充功能。
2. 從[網站首頁的「🧩 歸檔助手 V0.6.6」](https://eyvind95.github.io/hello/apps/gal-archive/index.html)下載 ZIP，或直接下載 `chrome-extension/gal-archive-chrome-v0.6.6.zip`。解壓縮後把其中六個檔案複製到**原本已安裝的擴充功能資料夾**，選擇覆蓋。
3. 進入 `chrome://extensions`，按原擴充功能的「重新載入」，確認版本 0.6.6，並重新整理已開啟的 ChatGPT 頁面。
4. 回 ChatGPT 對話，逐一確認每個對話綁定的輪迴及管理人。
5. **不要直接刪除舊擴充再重新安裝**：這樣可能失去 Chrome 儲存的私有寫入金鑰；若無法保留舊資料，須到網站重新建立寫入金鑰。

## Firebase 部署

本次 V5.0 **沒有變更 Cloud Functions 的伺服器程式**，之前部署成功的 `archiveIngest` 可以沿用。

若日後更新 `functions/index.js`，先覆蓋電腦本機檔案，再於 `apps/gal-archive` 資料夾執行：

```bat
firebase deploy --only functions:gal-archive --project eyvind95-182f0
```

如遇 `fetch failed` 可先看 `firebase-debug.log`，不要盲目多次重部署。

## 安全

- Chrome 寫入金鑰只供自己的私有 Firebase 端點使用。**不要**發到 Discord、GitHub、公開頁面或截圖裡。
- 新訊息自動歸檔只抓取得到的 ChatGPT 頁面可見文字，並不會自動下載 ChatGPT 全部舊歷史。
- 不同世界觀和輪迴間的轉移都是使用者明確批准後才生效，不以名稱猜測對應。

## 2026/11/21 長篇訊息「顯示較多」修復

- Chrome 擴充功能 V0.5.3：對已載入的玩家／GPT 長訊息，先嘗試按「顯示較多」展開再擷取。遇到仍未展開的頁面，不進行歷史回補，以免只儲存前半段；診斷顯示未展開訊息數。
- 網站 V5.1：「☁ 雲端同步」新增「🧽 清理『...／顯示較多』」。可選目前輪迴或全部輪迴；掃描已歸檔的自動來源，預覽訊息尾端修改，匯出 JSON 備份後更新本機與 Firebase 輪迴內容。
- **清理只移除截斷介面的多餘字樣，不能補回之前未擷取的正文**。舊版已收取的來源有去重限制，不能假定重新回補會覆蓋既有已收取資料。請先備份並核對缺少的長篇，必要時手動由原對話完整展開後修補正史。
- 目前雲端分類收取也會拒收仍含尾端「...／顯示較多」的來源，避免直接污染正式正史；這種來源仍保留在待收取匣以供核對。

## 2026/11/22｜V5.35 網站 × V0.7.0 ChatGPT／Gal AI 雙掃描助手

- 新版 Chrome 擴充功能新增完全獨立的 Gal AI 頁面掃描器。舊版 ChatGPT 監看／27%慢掃仍保留，且不會因為 Gal AI 來源覆蓋而影響副駕駛聊天。
- Gal AI 使用 activeTab 權限，只在使用者點選的 Gal AI 分頁注入。先在原頁面定位輪迴開場，再執行 31% 捲動（最多 350px）、420ms 等待加 350ms 穩定時間。不點開時間選單或隱藏的展開介面。
- 第一則左側無時間的訊息進 `opening`，後續的玩家、Gal AI 角色互動進 `messages`，世界事件另進 `events`；遊戲日期時間只從 Gal AI 回覆讀取，同回合玩家與 Gal AI 共用。藍色引用框、斜體等格式盡量轉為 Markdown 保留。
- 掃描只產生 `gal-ai-authoritative-scan` JSON；遇到開場、訊息身份、時間、回合連續性、世界觀或 DOM 偵測失敗會停止，不會寫入半份正史。
- 網站首頁「🌐 Gal AI 原生正史覆蓋」必須先選擇目標輪迴、匯入掃描 JSON、預覽並下載原輪迴備份；正式套用只取代該輪 `opening`、`messages`、`events`，其他分頁與其他輪迴不改。匹配到舊事件時保留接取狀態；若舊已接事件無法匹配，須額外確認。
- 本版本初次整合仍需實際 Gal AI 網頁 DOM 驗收；不應宣稱已在使用者真實帳號執行。官方 Firebase 仍使用原有手動同步流程，新掃描資料不會自動傳上雲端。
